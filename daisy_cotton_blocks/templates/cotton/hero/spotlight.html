{% comment %} ============================================================ — full-bleed image behind centred copy The editorial arrangement: a photograph or an illustration filling the block, dimmed, with the copy over it. Reach for it when the image is the argument — a place, a piece of equipment, a person — and there is no interface worth showing. ── Two things this block deliberately does not use ───────────────────────── **Not daisyUI's `.hero`.** That component is a one-cell grid, and it places every child into that cell with `grid-row-start:1; grid-column-start:1` — including an absolutely positioned one. A definite grid placement makes the grid *area* the containing block, and a grid area sits inside the container's content box, so `inset-0` on the image stops at the padding edge and leaves a bare band the height of the vertical padding above and below the picture. A plain positioned block gives the image the padding box, which is what "full bleed" means. **Not `.hero-overlay`.** It already carries its own 50% alpha, so an opacity utility on top multiplies rather than sets: the strongest setting came out dimmer than daisyUI's own default and the control read backwards. The overlay here is a solid `bg-neutral` layer whose opacity *is* the setting. ── The image ─────────────────────────────────────────────────────────────── An layer, not a CSS `background-image`. Three reasons, in order: an author-supplied URL interpolated into a `style` attribute is a CSS injection surface that escaping alone does not close; an carries `alt`, so an image that means something can say so; and a project that later wants `srcset` or `loading` can pass them straight through. Because the image is the project's and its brightness is unknown, `dim` is the control that makes the copy readable. Treat "does the copy still read over this picture?" as the setting's whole purpose. Attributes image URL of the background image, required for the layer to render alt alternative text.
